# Планирование астрономических наблюдений

РБПО, БАС2402, Панкова К. П.

Учебный REST API для планирования наблюдений небесных объектов. Наблюдатель выбирает объект и телескоп, назначает время сеанса, ведёт записи и завершает или отменяет наблюдение.

## Предметная модель

| Сущность | Назначение и связи |
|---|---|
| Пользователь | Наблюдатель. Один пользователь проводит несколько сеансов. |
| Небесный объект | Объект наблюдения с типом и минимальной апертурой телескопа. |
| Телескоп | Оборудование с апертурой и признаком доступности. |
| Сеанс | Связывает пользователя, объект и телескоп; хранит интервал и статус. |
| Наблюдательная запись | Относится к одному сеансу; содержит описание, время и оценку качества от 1 до 5. |

PostgreSQL проверяет внешние ключи, уникальные имена, положительную апертуру, корректный интервал и диапазон качества. При удалении пользователя, объекта или телескопа база удаляет связанные сеансы, а вместе с сеансом удаляет его записи.

## Запуск

PostgreSQL должен работать на `localhost:5432`.

```bash
cp .env.example .env

set -a
source .env
set +a

psql -d postgres -v db_password="$DB_PASSWORD" -f database/setup.sql
./mvnw clean spring-boot:run
```

Скрипт `database/setup.sql` создаёт БД `rbpo`, пользователя `rbpo_app`, все таблицы, индексы, ограничения и демонстрационные записи. Инструменты миграции не используются. Повторный запуск скрипта не удаляет пользовательские данные и не дублирует демонстрационные записи.

Проверка тестов:

```bash
./mvnw clean test
```

## REST API

Для каждого ресурса доступны операции `GET`, `GET /{id}`, `POST`, `PATCH /{id}` и `DELETE /{id}`:

| Ресурс | URL |
|---|---|
| Пользователи | `/api/users` |
| Небесные объекты | `/api/celestial-objects` |
| Телескопы | `/api/telescopes` |
| Сеансы | `/api/observation-sessions` |
| Записи | `/api/observation-records` |

Сервер возвращает ошибки в формате `application/problem+json`: `400` для неверных данных, `404` для отсутствующего ресурса и `409` для конфликта состояния.

## Бизнес-операции

| Метод и URL | Правило |
|---|---|
| `POST /api/observation-sessions/{id}/start` | Начинает сеанс в статусе `PLANNED` и занимает доступный телескоп. |
| `POST /api/observation-sessions/{id}/complete` | Завершает текущий сеанс с записью наблюдения и освобождает телескоп. |
| `POST /api/observation-sessions/{id}/cancel` | Отменяет запланированный или текущий сеанс; текущий сеанс освобождает телескоп. |
| `POST /api/observation-sessions/{id}/reschedule` | Переносит запланированный сеанс после проверки интервала и расписания телескопа. Тело: `startTime`, `endTime`. |
| `POST /api/observation-sessions/{id}/change-telescope` | Назначает запланированному сеансу другой доступный телескоп с подходящей апертурой. Тело: `telescopeId`. |

Сервис выполняет эти операции в транзакциях. Он блокирует изменяемые строки, проверяет статус связанных объектов и не допускает пересечения сеансов одного телескопа. Статус сеанса меняют только операции `start`, `complete` и `cancel`.
